# 分區地圖：來源與模型說明

## 資料責任與更新

Flask只讀SQLite。`run.py`啟動三個獨立程序：網頁、官方來源蒐集、氣象／模型 worker。官方來源仍依6h、24h、168h節奏檢查；氣象每日取得，錯誤一小時後重試；成功的歷史氣象增量回抓7日以補重分析發布延遲。初始化每次請求間隔8秒，429即停止本輪。無網路時官網資料與最後成功氣象仍可查閱。

官方原文按內容雜湊保存，來源日期、觀測日期、取得時間分開。資料來源：[日光市觀光協會](https://www.nikko-kankou.org/flowering/autumn-leaves)、[氣象廳生物季節](https://www.data.jma.go.jp/sakura/data/index.html)、[JMA品質碼與跨年規則](https://www.data.jma.go.jp/sakura/data/pdf/mikata.pdf)、[紅葉觀測方法](https://www.data.jma.go.jp/sakura/data/kaede2020.pdf)。紅葉定義為標本木大部分葉片轉紅的首次日期，不是景點見頃。

景點介紹 `best_period` 獨立為 `usual_period`。前台只把 `forecast.kind=official_outlook` 呈現為官方預測。catalog_reference保持API相容，但不冒充官方。官方預測按來源年度隔離，歷年事件不視為今年實況。景點固定排序與所選日期無關。

## 氣象快照

[歷史API](https://open-meteo.com/en/docs/historical-weather-api)指定 `models=era5`、[預報API](https://open-meteo.com/en/docs)指定 `models=gfs_seamless`，取得日均2m氣溫，時區Asia/Tokyo。近期預報請求16日與過去7日，實際只使用回傳的非空日期，不將請求天數当作供應商一定可用的範圍。更遠日期用過去已完成年度的每日氣候情境，不假裝整季天氣預報。

`weather_fetches`逐次保存供應商、指定模型、城市參考座標、取得時間、有效日期範圍、請求網址、原始JSON路徑、日溫資料。原始回應存在 `data/raw/open-meteo`。最新預報使用單一最新快照，不拼接過時預報。歷史快照按時間合併增量。`weather_attempts`保存整輪成功／失敗及城市錯誤。

座標為城市中心參考，不是精確標本木位置，也不代表景點海拔。Open-Meteo的格點回應座標可由原始JSON查閱。資料為Open-Meteo提供的氣象模型输出，來源須標示並遵循其[授權資訊](https://open-meteo.com/en/licence)。

## 紅葉模型

版本 `momiji-ridge-v1`。每個城市取目標年以前最近最多20個完整年度、至少15筆有效同樹種紀錄。採 `rm=8/9` 正規種目（いろはかえで）；`rm=6/7`可能包含不同替代種名，未完成逐年核對前不使用，官方原紀錄仍保留。秋季事件隔年一月依JMA季節年度延展，不錯算成年初極早紅葉。

基準為站點有效訓練年紅葉日期中位數。計算每站8、9、10月日均溫完整月份平均及訓練年正常值，再以月溫偏差、站點日期相對基準的天數，訓練共享ridge線性校正。特徵標準化；固定alpha=10；截距不懲罰。無numpy或機器學習框架依賴，4×4正常方程採部分主元消去求解。沒有使用測試年度調參。

發布時已完成天氣使用歷史快取（至少落後發布日5日）。其餘先採本次實際近期預報，再逐個训练年填入未來每日氣溫，得到最多20個日期情境。單城取中位數及10–90百分位。區域中位為有效城市中位日期的中位數；區域下界取城市下界10百分位，上界取城市上界90百分位，保留城市及樣本年度清單。這是城市與情境分布，不是經校準的信心區間，不代表山區、全部海拔或個別景點。

分段導覽：下界14日前綠、其後到下界前黃、區間内橘紅、區間後褐、無資料灰。選取外框只表示操作焦點，不改填色。褐色不能當作落葉觀測。櫻花使用滿開事件歷年基準與粉色區間，未加入櫻花氣象模型。

## 回測與發布門檻

最新五個已完成季節年，逐年向前留出，每年10/1、10/15、11/1。每折所有站点正常值、日期基準、迴歸係數與情境年都只由更早最多20年建立。同折／發布日的基準與模型採相同有效城市及資料截止條件。真值僅計算誤差，不進入特徵或訓練。缺少應已取得的天氣天數時不計入該案例。

沒有歷史預報發布快照可重播，回測未完成月份只用旧年氣候情境。ERA5為目前版本的重分析，以5日延遲模擬取得條件，這是嚴格時間截斷，但不是原始資料版本重播。報告明示限制，不宣稱完成完美实时回放。

需五年度、至少100案例、平均絕對日期誤差改善10%才啟用。未過門檻保留完整模型／係數／逐案例報告，前台使用未經天氣校正的歷年基準。不足15年則灰。`model_runs`每次保存發布時間、截止日、版本、來源快照、回測報告及城市估計；相同輸入不重算。最近一次氣象更新失败不替換已啟用的前次成功發布，API標為過期；正常發布超48h也標過期。

## 模組與儲存

- `store.py`：保留places／observations／historical／outlooks／collection_runs，新增weather_fetches／weather_attempts／model_runs。
- `collect.py`：官方蒐集與權威年份解析，模型不寫此來源。
- `weather.py`：氣象請求、原始回應、快照，背景入口。
- `model.py`：pure Python ridge、時間情境、防洩漏回測、報告與發布。
- `regions.py`：唯讀分區與城市彙總、歷年備援、分段規則。
- `service.py`：景點實況／官方預測、原有來源與歷史服務。
- `app.py`：唯讀API；static/templates：響應式分區導覽、即時日期重繪、內嵌卡片。

背景程序可寫的表各自分開；模型測試對官方四張表前後逐列比較，確認完全未變。無任何HTTP頁面讀取觸發遠端蒐集／訓練。
